# Общий чат

Развёрнут 14 октября 2026: браузер → `https://api.inteonmteca.online` →
API Gateway → Cloud Function → YDB Serverless.
Сайт и API находятся на одном site, но разных origins: CORS разрешает только
`https://inteonmteca.online`, запросы передают HttpOnly/Secure/SameSite=Lax cookie.
Ответы API имеют `Cache-Control: no-store` и не проходят через CDN сайта.

- Postbox: отправитель `noreply@inteonmteca.online`, DKIM TXT `inteonchat._domainkey`, SPF в корне домена. Закрытый DKIM-ключ хранит Postbox.

Чат хранит последние 50 сообщений в общей записи. Изменение истории, проверка
сессий и ограничения частоты выполняются в serializable-транзакциях, поэтому
параллельные экземпляры функции не перезаписывают сообщения друг друга.
Сессии, одноразовые коды и счётчики имеют срок действия и удаляются по TTL.
В YDB включены защита от удаления и ежедневные резервные копии на 7 дней;
лимит — 50 RU/с и 1 ГБ, provisioned capacity не включена.

По запросу владельца вход гостевой: один код показывается на экране и
отправляется на почту. Это **не подтверждение владения почтой**. Запросы кода
имеют отдельный случайный challenge; ввод одного адреса на другом устройстве
не отменяет предыдущий код. Сбой Postbox записывается только в серверный журнал,
не возвращается как ошибка входа и не мешает использовать экранный код.
Сервер не журналирует адреса, коды и токены. Полный адрес не входит в публичную историю.

## Обновление

```powershell
python -m unittest discover -s tests -p test_cloud_chat.py -v
node --test tests/auth-fallback.test.cjs
python tests/browser_shared_chat.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-chat.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-site.ps1
```

`deploy-chat.ps1` пакует только Python-обработчик и requirements, выпускает
версию функции, не заменяя базу, и проверяет публичный `/api/runtime`.
Проверить `/api/chat`, вход и обмен сообщениями в двух независимых браузерах.
Почтовые подтверждения принятия к отправке видны как `login_email_accepted`
в журнале функции; это не подтверждение поступления во входящие.

Для отката backend можно вернуть tag `$latest` на предыдущую версию функции,
не создавая новую базу. Для фронтенда сохранять предыдущий опубликованный HTML.
Изменения схемы выполнять отдельно до публикации использующей их функции.

Старые `inteonmteca-local-*` записи сохраняются в браузере, но больше не
используются как общая история или подтверждённая серверная сессия. Они никогда
не поступали на сервер; автоматический импорт не выполняется.
