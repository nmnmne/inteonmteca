## Что исправлено

- Debug, тема и вход используют общий координатор: одна открытая плавающая панель, ограничение ширины 360 px и высоты доступным viewport, единый слой, Tab/Shift+Tab внутри панели, Escape с возвратом фокуса. Вложенное меню сначала обрабатывает свой Escape. Inline-чат остаётся частью страницы.
- Элементы Debug объединены в один контейнер вместо нескольких независимых фиксированных вертикальных позиций. Debug выключен при загрузке и возвращении назад; скрытая панель не обновляет DOM. Нужные мобильные эффекты доступны.
- Убраны конфликты шапки на landscape, наложение счётчика посещений на ссылку во двор, неподходящая ширина панелей на планшете. Активные области основных мобильных кнопок — 44 px.
- Мобильная строка резервирует две строки названия и отдельную строку исполнителя. Размер определяется типографикой, а не растянутым контейнером: это устраняет обратную связь при refit. Одно CSS-выражение владеет итоговой высотой строки. Первичный desktop-fit выполняется сразу и не ограничивается четырьмя HTML-заглушками.
- Чат стартует свёрнутым, при раскрытии выделяет пять строк сообщений; после возвращения назад снова свёрнут. Статус и время плеера проверены во время настоящего локального воспроизведения. Desktop → mobile → desktop восстанавливает восемь desktop-слотов.
- Загрузка обложек ограничена двумя параллельными декодированиями. Сначала реальный файл 16 px, затем подходящий размер по CSS × DPR. При слабой сети/низком качестве задержка улучшения увеличивается. Изображение заменяется после decode, без промежуточного пустого кадра. Невидимые копии не получают постоянное наблюдение геометрии.
- Буквы сохраняют прежнюю скорость и бюджет обновлений. В поддерживающих браузерах декоративная маска стала псевдоэлементом: один DOM-элемент на букву вместо двух. Исходный текст остаётся доступен скринридеру; есть fallback со старой aria-hidden маской. Проверка `:focus-visible` вынесена из цикла по буквам.
- У существа убран постоянный пересчёт препятствий каждые 240 мс: теперь он вызывается изменениями layout/состояния. Убраны бесполезный 50-мс таймер старого режима названий в catalog и скрытые обновления theme-контролов.
- Контроллер качества учитывает перегрузку букв/layout даже во время паузы canvas; такая пауза не служит основанием повысить графику. Мобильный alternate-logo стал пассивным оформлением и не занимает слот foreground-эффекта.
- Убрана предварительная загрузка двух картинок двора с главной. Нижние скрипты переведены на defer с сохранением порядка. Подготовлена публикация gzip CSS/JS под именами с хешем и immutable-кэшем; HTML загружается последним. Хешированные обложки получают такую же длительную политику кэша.

## Проверка компоновки

Edge/Chromium, настоящие pointer/keyboard действия в Playwright. Для четырёх мобильных размеров включены touch/coarse. Каждый размер проверен со шрифтом 100% и 200%, открытием всех трёх панелей, сменой активной панели, обходом Tab и Shift+Tab, Escape, reload, раскрытием/сворачиванием чата и измерением bounding boxes.

| Viewport | Строки списка при обычном шрифте | Высота строки | Итог |
|---|---:|---:|---|
| 320×568 | 4 | 58 px | Панели внутри экрана, текст и исполнитель внутри плитки |
| 390×844 | 6 | 58,3 px | Чат, список и плеер не пересекаются |
| 844×390 | 3 | 58,7 px | Мобильная landscape-компоновка; шапка и панели в границах |

Увеличенный шрифт уменьшает число строк, а не высоту букв. Очень длинное название ограничено двумя строками; полная строка остаётся в DOM. Число плиток сознательно не является неизменным требованием для всех размеров.

В `acceptance/` сохранены снимки закрытой страницы и каждой панели для каждого размера и масштаба шрифта. Проверены также возврат из другой страницы, восстановление desktop-слотов и accessibility tree декоративных букв. Полный сценарий — `tests/browser_followup_acceptance.py`.

## Загрузка и изображения

Сетевой прогон: локальный HTTP-сервер, холодные контексты браузера, API заменён стабильными ответами. В версии «после» сервер воспроизводит подготовленное gzip-сжатие CSS/JS; на публичном сервере оно ещё не включено. Вес ниже — transferSize подресурсов, не размер исходников на диске; HTML и начатое пользователем аудио в него не входят. Ротация даёт небольшую вариацию суммы.

| Метрика | До | После |
|---|---:|---:|
| 390×844, начальные подресурсы | 1 014,7 КБ | 352,0 КБ |
| Диапазон обычных размеров | 1 012–1 016 КБ | 348–352 КБ |
| Slow 3G: первый контент | 8,040 с | 2,664 с |
| 4G: первый контент | 2,020 с | 0,944 с |
| CLS 1280×650 | 0,1690 | 0,0169 |
| CLS 1440×900 | 0,0873 | 0,0072 |
| CLS медленной загрузки | около 0,299 | около 0,068 |

Условия: slow 3G — задержка 400 мс, 50 000 байт/с; 4G — 150 мс, 200 000 байт/с. Это воспроизводимая эмуляция, не обещание времени загрузки из любой сети. На обычной мобильной загрузке итоговый CLS — 0; при медленной сети остался небольшой начальный сдвиг сцены, не смены обложек.

Исходная база уже содержала маленькие rendition-файлы. Поэтому старую оценку 3–5 МБ из брифа нельзя выдавать за непосредственно измеренное «до» этой правки.

- DPR 1/2/3 проверены отдельно с работающим браузерным кэшем: первая ступень 16 px, следующие обычно 24/32 px; разрешённые кандидаты 16/24/32/48/64 px. Размер декодированного изображения не превышал 64 px.
- В холодных мобильных прогонах повторных сетевых запросов одного URL обложки не было. В desktop повторялся `/api/chat` при открытом чате — это polling, а не дублирование изображений.
- Повторная загрузка и явное повторное декодирование ранее загруженного URL подтверждены нулевым transferSize и отсутствием нового запроса на локальный сервер с immutable-заголовком. Явный URL нужен, поскольку случайный порядок треков после reload может вообще не совпасть.
- В продолжительном 57-секундном прогоне ротации ни одного обращения к оригинальной большой обложке. Переходы preview → sharp записаны по реальным событиям загрузки. Видимость и near-viewport обслуживают разные observers.
- Дополнительно выполнен полный видимый цикл `God Is Dead`: подтверждены все 15 разных индексов обложек, запросов оригиналов нет. Снимки ступеней и журнал находятся в `cover-cycle/`.
- Скрытый дубликат плеера не загружает исходную большую обложку. Два preload двора удалены с главной; двор по-прежнему загружает свои ресурсы при переходе.

## Производительность: сопоставимые измерения

Во время работы частота кадров среды менялась примерно со 120 до 32, затем до 57 Гц. Поэтому первоначальные раздельные числа CPU «до/после» **не доказывают ускорение вдвое**. Финальное сравнение выполнено соседними запусками в одном браузере: старая → новая, затем новая → старая, один viewport 390×844, DPR 2 и одинаковый seed случайности. Старые файлы читаются через Git в отдельный HTTP-сервер; рабочие файлы не откатываются.

| Условие | До | После | Интерпретация |
|---|---:|---:|---|
| Без throttle, сопоставимая пара около 57 кадров/с | 15,8% занятости; 2,78 мс/кадр | 14,6%; 2,57 мс/кадр | Небольшой выигрыш, один сопоставимый повтор |
| CPU 4×, два повтора около 56,5 кадров/с | 75,4%; 13,49 мс/кадр | 68,7%; 12,23 мс/кадр | Около 9% меньше работы главного потока |
| CPU 6×, два повтора | 98,9%; около 41,4 кадров/с | 96,8%; около 45,1 кадров/с | Больше кадров, но поток остаётся почти полностью занят |
| DOM при одинаковом seed | 1 453 элемента | 1 132 элемента | Примерно на 22% меньше элементов |

TaskDuration / время выборки измеряет занятость главного потока браузера, **не загрузку всего процессора/видеокарты**. RAF отражает выдачу кадров этой среды, не физический FPS телефона. Первый повтор без throttle пересёк смену системной частоты и исключён из вывода об ускорении.

Полные записи: `paired/report.json`, сценарий `tests/browser_followup_paired.py`. Локальные API заглушены: задержки настоящего сервиса и авторизованный пользователь не являются предметом этого теста.

### Long tasks

В полном холодном прогоне у 390×844 без throttle не было задач >50 мс ни до, ни после. При CPU 4× было 9 / 8 таких задач, максимальная 216 / 222 мс; при CPU 6× — 18 / 11, максимальная 302 / 162 мс. Это описательные результаты разных прогонов с разной частотой среды, **не отдельное доказательство процентного ускорения**. Первый запуск браузера 320×568 имел одну длинную задачу 244 / 277 мс. Заявлять полное отсутствие длинных задач нельзя.

## Эффекты и скрытая работа

- При уровне 1 настоящий браузер завершил Scatter за 4,32 с, Dissolve за 10,94 с, Recursion за 6,52 с. Ambient 5/5 не удваивает их длительность.
- Одна foreground-сцена одновременно; попытка параллельного запуска отклоняется. Вес мобильной ротации 5:5:1 проверен тестом планировщика. Браузер подтвердил доступность каждого из трёх эффектов; статистический многочасовой прогон частот не проводился.
- Visibility-переход проверен управляемыми событиями `document.hidden`: сцена освобождает владение и возобновляется. Это не заявляется как тест физического сворачивания приложения на iOS/Android.
- За 57 с на уровне 1 зарегистрировано 30 480 изменений декоративных букв. Обёрнуты 10 из 63 повторённых строк, а не все три копии целиком. Скорость и бюджет букв не уменьшены ради цифр CPU.
- За тот же период: 0 DOM-записей скрытого Debug, 0 запросов свёрнутого чата, 0 созданных для автоматического выбора устройства WebGL-контекстов. В консоли браузерных сценариев нет необработанных JS-ошибок.
- Декоративные RAF остаются отдельными, но останавливаются собственными lifecycle/quality/scene gates. Переписывание всех рендереров в единый mega-loop не выполнялось: оно само по себе не гарантирует выигрыш.

## Решения по спорным настройкам

| Настройка | Решение |
|---|---|
| no-store у hashed обложек | Изменить на immutable, 1 год; подготовлено в deploy |
| Старые rendition-файлы и sync без delete | Оставить старые хеши: они нужны старым HTML и кэшам. Автоматического удаления нет; будущая очистка только по манифестам сохранённых релизов |
| CSS/JS и обновление | Публиковать gzip под хешированным именем, HTML последним; исходные совместимые имена остаются. Неизменённые ресурсы переиспользуются |
| Parser-loaded JS | Нижние 26 скриптов defer, включая новый coordinator; ранний room-portal оставить для корректного первого показа страницы |
| Ленивая загрузка всего подряд | Не вводить: сохранить порядок общих зависимостей. Тяжёлые операции выполнять по событию, а не на скрытой панели |
| Ambient 5/5 | Сохранить для фона, foreground-длительность считать отдельно |
| Debug в production | Сохранить, по умолчанию выключен, скрытые DOM-обновления остановлены |
| Theme picker | Сохранить UX; скрытый sync не обновляет DOM, лишний observer темы убран |
| Чат | Polling только когда чат действительно открыт и страница видима |
| Landscape/breakpoint | Мобильный coarse-layout имеет явный приоритет; desktop-слоты возвращаются |
| Несколько владельцев высоты строк | Один итоговый CSS-размер, типографический минимум, синхронный первый fit |
| Три копии каталога | Сохранить непрерывную прокрутку; не размножать загрузку и glyph-обёртки для всех копий |
| GPU/CPU «самое мощное устройство» | Автоматический перебор не выполнять. Браузер/ОС выбирают адаптер. Уровень зависит от измеренной нагрузки; диагностика устройства запускается явно |
| Alternate-logo на mobile | Пассивное оформление, не держит эксклюзивный слот пользовательских эффектов |
| Старые режимы script.js | Отключить подтверждённо пустой catalog-таймер; не удалять ветки вслепую, пока другие страницы/режимы могут от них зависеть |

## Границы результата и следующий уровень

Нельзя обещать одинаковую плавность на всех телефонах: CPU 6× всё ещё насыщает основной поток. Не проверены физический Android/iOS, виртуальная клавиатура настоящего устройства, реальное RDP-видеокодирование, авторизованный production API и новый публичный кэш после выкладки. Нет смысла объявлять конкретную модель CPU/GPU минимальным требованием по одной эмуляции.

Следующий измеримый шаг — профиль главного потока на реальном слабом телефоне при проигрывании, прокрутке и открытом чате. Если буквы остаются главным потребителем, переносить декоративный слой на общий canvas, сохранив обычный доступный текст и прежнюю скорость. Затем рассмотреть одно физическое окно каталога вместо трёх DOM-копий. Делать по отдельности, с визуальным сравнением и временем кадра; разделение script.js на модули полезно для сопровождения, но не заменяет измеренную оптимизацию.

Отдельное подтверждение публикации получено после проверки: «пуш и деплой». Публичная проверка выполняется после выкладки; приведённые выше измерения относятся к локальным испытаниям.
